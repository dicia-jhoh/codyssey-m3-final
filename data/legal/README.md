# 법령 조문 — 담당: 김기훈 (지금은 검증된 샘플 4건)

`rag.py`가 근거로 인용하는 법령 원문. `articles.jsonl`에 한 줄 한 조문씩 적고,
`backend/scripts/load_legal_articles.py`로 Chroma에 넣는다(Chroma DB 자체는
`data/legal/chroma/`에 생기는데 `.gitignore` 대상이라 — 이 JSONL이 진짜
원본이고, DB는 이 파일에서 언제든 다시 만들 수 있는 생성물이다).

## 형식

`data/testset/labels.jsonl`과 같은 패턴 — 한 줄 = JSON 객체 하나.

```json
{"law_name": "국민건강보험법", "article_no": "80", "quote": "원문 그대로", "claim": "쉬운 말 풀이 한 줄", "source_url": "검증한 출처", "verified_at": "YYYY-MM-DD"}
```

- `quote`: 조문 원문에서 **잘라 오기만** 한다 — 단어를 바꾸거나 요약해서 새 문장을
  만들지 않는다(화면에 "원문 인용"으로 그대로 나간다). 길면 `…`로 생략 표시. 쉬운
  말 풀이는 `claim` 쪽 몫이다. (한 번 이슈로 지적받음 — 호별 계산식을 "…100분의
  3에 해당하는 금액을 가산세로 부과한다"처럼 그럴듯한 문장으로 바꿔 썼다가, "원문에
  없는 문장"이라고 걸렸다. 조문이 항·호로 쪼개진 계산식이면 그 중 한 호를 통째로
  그대로 옮긴다.)
- `claim`: `quote`를 쉬운 말로 풀어쓴 한 줄(`schema.Basis.claim`에 그대로 들어감).
- `article_no`: "제80조의2"처럼 가지조문이면 `"80의2"`로 적는다(`rag._citations()` 참고).
  항·호 단위까지 밝히고 싶으면 `note`에 적는다(예: `"note": "①항 3호"`) — 매칭
  로직에는 안 쓰이고 사람이 보는 참고용.
- `source_url`·`verified_at`: 나중에 다시 확인할 때 쓴다. 법은 개정된다 — 특히 벌금·연체금
  같은 숫자는 주기적으로 재확인이 필요하다.
- **PR 올리기 전 체크**: `quote`를 `source_url`의 law.go.kr 원문과 한 글자씩 대조했는가?

## 지금 들어있는 것과 검증 방법

### 1. 국민건강보험법 제80조(연체금)

law.go.kr의 "조문정보" 링크(시행일자 2026.10.8로 명시됨)와 다른 출처(nepla.ai) 두
곳의 내용이 일치하는 걸 교차 확인하고 넣었다 — 처음 검색했을 때 한 출처(위키문헌)가
더 예전 버전(연체금 계산식이 다름: 월단위 vs 일단위)을 보여줘서, 교차 확인 없이
하나만 믿으면 틀린 조문이 "근거"로 나갈 뻔했다.

⚠️ **2027-01-01 시행 예정 개정**(법률 제21687호, 2026-05-26 일부개정)이 이미 확인됨 —
연체금 비율이 인하된다. 그 날짜가 지나면 이 조문도 다시 확인해야 한다.

### 2. 지방세기본법 제55조(납부지연가산세)

이번엔 **세 번 충돌**했다: ①첫 검색 요약은 "지방세징수법 제8조"가 관련 조문이라고
했는데, 실제 그 조문은 "납부고지서 발급 시기"로 완전히 다른 내용이었다. ②다음 검색
요약은 "지방세기본법 제55조"가 맞다고 했지만(nepla.ai와 일치), ③또 다른 검색 요약은
같은 "지방세기본법 제55조"를 "불복(이의신청)" 조항이라고 했다 — 서로 다른 lsJoLnkSeq
permalink를 섞어 짚은 것으로 보인다. law.go.kr "조문정보" 링크(시행일자 2026.10.2,
법률 제22017호)로 직접 확인하고서야 "납부지연가산세"가 맞다고 확정했다.

지방세는 지방세법·지방세기본법·지방세징수법·지방세특례제한법으로 쪼개져 있어서
국민건강보험법보다 조문 찾기가 훨씬 헷갈린다 — **지방세 관련 조문을 추가할 땐 법령명
자체(어느 법인지)부터 law.go.kr "조문정보" permalink로 재확인할 것**, 검색 요약의
법령명을 그대로 믿지 말 것.

`quote`는 확인된 것 중 가장 단순하고 확실한 부분(①항 3호 — 기한 내 미납 시 즉시
3% 가산)만 담았다. 월 단위로 더 붙는 부분(4호)·한도(100분의 75)는 법령 요약마다
표현이 달라 보수적으로 뺐다 — 필요하면 재검증 후 추가한다.

### 3. 국민연금법 제97조(연체금)

국민연금 고지서용(어르신 1차 타겟에 특히 자주 오는 고지서). 이번엔 **law.go.kr
"조문정보" permalink를 못 찾았다** — 검색으로 나온 lsJoLnkSeq 두 개를 시도했는데
각각 "보험업법 제97조 제4항"·"소득세법 제12조"로 **완전히 다른 법 조문**이 나왔다
(법률마다 그 조문만의 permalink ID가 있어서 추측으로 안 맞는다). 대신:

- nepla.ai(국민연금법/20260617 — 날짜가 버전) 본문에서 제97조①항 원문을 확인
- 같은 페이지의 "법률 제21203호(2025.12.16. 일부개정)" 버전 정보가 law.go.kr에서
  별도로 직접 확인한 "국민연금법 시행일자 2026.6.17., 법률 제21203호"와 **정확히
  일치** — 날짜가 다른 두 조회가 같은 법 버전을 가리킨다는 뜻이라 신뢰도를 높였다
- 헌재결정례("국민연금법 제97조 제1항 위헌확인", 2011헌마458)가 제97조①항을
  "연체금" 관련 조항으로 다루고 있어 제3의 독립 출처로도 부합

⚠️ **위키문헌의 국민연금법 제97조는 완전히 다른 내용("독촉")이었다** — 지금까지
겪은 "오래된 버전" 패턴과 달리 이번엔 조번호 자체가 개정 과정에서 재배열된 것으로
보인다(위키문헌이 과거 어느 시점 버전을 그대로 보여줌). **조번호만 같아도 시점이
다르면 완전히 다른 조문일 수 있다** — quote를 가져온 출처가 정말 "지금" 버전인지
(날짜/법률번호로) 반드시 확인할 것, 조번호가 같다고 안심하지 말 것.

`quote`의 징수기관이 "건강보험공단"인 건 오타가 아니다 — 2011년부터 4대 사회보험료
(건강보험·국민연금·고용보험·산재보험)를 건강보험공단이 통합징수한다.

### 4. 질서위반행위규제법 제24조(가산금)

과태료 고지서용(주차 위반, 환경 관련 과태료 등 — 역시 어르신이 자주 받는 유형).
law.go.kr "조문정보" permalink(lsJoLnkSeq=900712576, 시행일자 2026.10.2)로 원문을
직접 확인했고, easylaw.go.kr(법제처 생활법령정보)가 "질서위반행위규제법 제24조"를
과태료 가산금의 근거 조문으로 지목한 것과 법령·조문 번호가 일치해 교차 확인했다.

이번에도 **검색 요약 하나는 가산금 비율을 "100분의 5"라고 틀리게 말했다**(실제는
①항 100분의 3 — ②항의 중가산금 1천분의 12와 섞여서 나온 추정). 역시 law.go.kr
원문 permalink를 직접 열어보지 않고 검색 요약만 믿었으면 틀린 숫자가 들어갈
뻔했다. `quote`는 ①항(즉시 3% 가산)만 담았고, ②항(매달 중가산금 0.12%, 최대
60개월)은 월 단위 계산이 필요해 보수적으로 뺐다.

## 다음 할 일 (김기훈 담당)

기획서 범위(초중등교육법 등 고지서가 자주 인용하는 법)로 조문을 더 모은다. 숫자
(금액·비율·기한)가 들어간 조문은 **반드시 law.go.kr "조문정보" permalink에서
법령명·조문 제목·시행일자까지 확인**하고, 가능하면 서로 다른 출처 두 곳 이상을
교차 확인한다 — 위 사례들처럼 검색 요약이 법령명·조문 내용·비율 숫자를 틀리게
알려줄 수 있다(매번 그랬다). "그럴듯한 검색 결과 하나"로는 안 된다. law.go.kr
permalink를 못 찾을 땐(제97조 사례처럼) 날짜/법률번호가 서로 일치하는 두 개 이상의
독립 출처로 대신하고, 그 경위를 이 문서에 남긴다.

```bash
cd backend
python scripts/load_legal_articles.py   # data/legal/articles.jsonl → Chroma에 적재
```
