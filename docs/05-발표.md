## 시연 대본

> 2026-10-18 기준 초안. 확실히 보여줄 수 있는 것과 아직 확인 안 된 것을 구분해서
> 적는다 — 발표 전 실제 API 키로 재검증되면 "확인 안 됨" 표시를 지운다. 안 되는 걸
> 된다고 적어두면 발표 중 그대로 들통난다.

### 확실히 되는 것 — 샘플 모드(API 키 없이도 항상 동작)

1. 팀 홈페이지(http://129.225.184.224:8037/)에서 팀 소개·필수 기술 요소 4종 체크 보여주기
2. 서비스 화면(http://129.225.184.224:8037/app/)에서 사진 아무거나 올리기
3. 「샘플 모드 — 실제 고지서가 아닙니다」 배너 — 왜 있는지 짚기(AI 윤리: 키가
   없거나 호출이 실패해도 화면이 안 깨지고, 그 사실을 사용자에게 숨기지 않는다)
4. 결과 화면: 원본 사진 위 3색 표시(빨강 48,200원 · 파랑 10.31까지 · 초록 납부서)
5. 할 일 카드: 「건강보험료 내기 · 2026-10-31까지 · 48,200원 · 은행 또는 앱 납부」
6. 근거: 「기한을 넘기면 돈을 조금 더 내야 해요」+ 원문 인용 + 「국민건강보험법
   제80조」— 이건 지어낸 예시가 아니라 law.go.kr에서 실제로 검증한 조문이다
   (`data/legal/README.md` 참고)

### 아직 확인 안 됨 — 발표 전 재확인 필요

- 실제 고지서 사진을 올렸을 때 진짜 추출이 되는지(`cd backend && python -m
  app.extract <사진>`로 미리 확인)
- 손주 모드 공유 링크
- n8n 기한 알림 실제 발송

### AI 활용 파트 발표 메모

- **황지영(AI 활용①)**: `extract.py`의 멀티모달 추출 — 비전 LLM으로 3색 좌표를
  어떻게 뽑는지, 금액·날짜 이중 확인이 왜 필요한지. 실제로 겪은 버그(PR #9 머지
  직후엔 테스트는 통과해도 실사진 검증이 안 된 상태였던 것, PR #15에서 고침)를
  "AI 활용 방식의 기술적 의사결정 근거" 사례로 쓸 수 있다 — README 「겪은 버그」
  절 참고.
- **김기훈(AI 활용②)**: `rag.py`가 "조문 번호로 먼저 거르는" 이유 — 고지서는
  법령을 「○○법 제○조」처럼 번호로 인용하니, 문장 유사도 검색만 쓰는 것보다
  정확하다(`docs/03-AI-설계.md` 「RAG」 절).

슬라이드 7(정확도 결과)은 `backend/scripts/score_testset.py` 실행 결과를 그대로
붙인다 — 숫자를 손으로 계산하지 않는다.
